# Design brief

## 1. Goal

Watch a library of online videos at home, at 1080p, without waiting and without depending on a third-party player. Tubes keeps the library (which channels and videos exist) itself, from YouTube's Data API; it fetches a video the first time someone plays it, and keeps copies on a large local disk so the next play is instant.

Decisions (2026-11-09): run on the home server (a residential connection; datacenter IPs are blocked); fetch on demand and stream while downloading rather than pre-download everything; 1080p where offered (a 4K screen); a 1 TB cache on a 10 TB disk, trimmed by a mix of recency and popularity; latest Chrome as the only player (VP9 and AV1 are fine). Later: predict what will be wanted, fetch it ahead and recommend it.

## 2. Architecture

- **Library (`catalogue.py` writes, `library.py` reads, `youtube.py` asks)**: ported in November 2026 from the storage service (a Cloudflare Worker over D1), which managed it until then. A channel added by link, id or @handle is followed; a sync reads its uploads playlist 50 at a time and asks for the details of videos not already held, 50 per call (one quota unit each). The first sync reads back to the first upload and saves its page token after every page, so one that stops (quota, restart) resumes there; after that a sync reads only the newest pages until one brings nothing new, so 20 channels cost a few dozen units, against storage, which re-read every page each time. A video added on its own brings its channel in unfollowed. The key is `YOUTUBE_API_KEY` (and `YOUTUBE_API_REFERER` for a site-restricted key) from the environment. `tubes sync` runs every few hours from a timer; Admin > Library adds, syncs (one background sync at a time, polled by the page), starts a channel again and removes it. A video YouTube no longer has is hidden, not deleted: each sync of every channel rechecks a rolling slice of the library, and a fetch yt-dlp says is unavailable marks it at once; a recheck or fetch that finds it again brings it back. Streams live now or scheduled are hidden until they end (from the Data API's `liveStreamingDetails`); a past stream or premiere is shown, but asked about again when a page reads it and it was not asked about in the last day, since a past stream's recording often goes soon after.
- **Database (`db.py`, `models.py`, `migrations/`)**: Tubes' own tables through [omarchy_db](https://github.com/jburnhams/database): the library (`channels` with their sync state, `videos`), `copies` (one row per cached video: state, size, formats, pinned) and `plays` (one row per play). Postgres in production (its own `tubes` schema in the shared database), SQLite in tests; SQL is kept portable.
- **Fetcher (`fetcher.py`, `ytdlp.py`)**: `POST /api/videos/{id}/play` records the play and, unless a copy exists, starts yt-dlp (format AV1 > VP9 > H.264 at `max_height`, width checked too, original audio) writing to stdout into ffmpeg, which writes an fMP4 HLS event playlist in the video's cache folder. The player starts once three segments exist. yt-dlp downloads itself (YouTube refuses ffmpeg's own requests) and asks as the `visionos` client, which skips a 4 s wait.
- **Cache (`cache.py`)**: score = Σ 0.5^(days since play / half-life). Eviction starts above 95% of the limit and stops under 90%, lowest score first; pinned copies, copies being fetched and unplayed copies younger than `protect_days` are kept; failed copies go first.
- **Server (`server/app.py`)**: FastAPI, JSON under `/api/*`, media under `/api/media/{id}/`, the built web app at every other path with a relative `<base>` (works behind a reverse proxy at a subpath).
- **Web app (`web/`)**: React 19 on strata-react; playback is Strata's `MediaPlayer` with its HLS engine (`strata-react/hls`, set up in `web/src/player.ts`). Two looks: the watching side (`web/src/watch/`, at `/`) keeps the old Tubes look, a video site's layout with Tubes' own mark and `tube-*` tokens (`web/src/styles/tube.css`); the admin area (`web/src/screens/`, at `/admin`: Library, Cache, System, Settings) uses Strata's components and a palette generated from the subject (`theme.generated.css`). Every read is `useLoad`/`useInfiniteLoad` with a skeleton and an empty state; long lists page by cursor (`published|id`), never by offset.

## 3. Principles

- **Generic**: nothing in the repo names real channels, videos or viewers; which channels are followed is data.
- **Credentials only from the environment** (the YouTube key).
- **Hermetic tests**: a stand-in yt-dlp, and a stand-in YouTube Data API (`tests/utils/`), no network; SQLite by default, `--pg` for Postgres.
- **Ratcheting coverage floors**: Python unit coverage (`fail_under` in `pyproject.toml`) and web combined coverage (`web/coverage-floor.json`) only go up.
